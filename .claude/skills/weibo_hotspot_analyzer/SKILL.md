# 微博热搜分析与产品创意生成（Weibo Hotspot Analyzer）

把微博实时热搜转化为可落地的产品创意。面向产品经理、创业者、内容创作者和市场研究者。

## 触发场景

- 用户想了解"现在什么最火 / 今天有什么热点 / 微博热搜榜"
- 用户想从热点中找产品灵感、创业方向、内容选题
- 需要做市场机会 / 用户需求洞察 / 蹭热点借势

## 执行流程

### 第 1 步：抓取热搜数据

优先运行抓取脚本（无第三方依赖，仅用 Python 标准库，Windows 上如 `python` 不可用可换 `py`）：

```bash
python ".claude/skills/weibo_hotspot_analyzer/scripts/fetch_weibo_hotspot.py" --top 50
```

脚本依次尝试多个数据源（微博官方 ajax 接口 → 微博 hot band → 公共聚合接口），取第一个成功的，输出结构化 JSON。

若脚本不可用（无 Python / 网络失败 / 全部数据源返回空），使用以下兜底方式，并在报告中注明使用了兜底数据：
1. `WebFetch https://weibo.com/ajax/side/hotSearch`，取 `data.realtime[].word`；
2. `WebSearch` 检索"微博热搜榜 今天"，整理榜单。

抓取后：
- 保留热度前 50 条；若不足 30 条，如实说明数据源受限。
- 若所有尝试均失败，停止并如实报告失败原因，**不要编造热搜词**。

### 第 2 步：分析热点

对每条热搜做结构化分析，重点找"信号"而不是罗列：

| 维度 | 说明 |
| --- | --- |
| 分类 | 娱乐 / 社会民生 / 科技互联网 / 财经 / 体育 / 教育 / 医疗健康 / 影视 / 游戏 / 电商消费 / 时政 |
| 热度分级 | S（爆，榜一或 num≥5,000,000）、A（热，1,000,000~5,000,000）、B（温，<1,000,000） |
| 事件主体 | 是什么人 / 什么物 / 什么事件 |
| 用户情绪 | 正面 / 负面 / 中性 / 争议 |
| 关联人群 | 谁最关心这条热点 |
| 衍生需求 | 热点会引发哪些后续需求：想了解、想买到、想讨论、想解决、想被安抚 |

产出：用 markdown 表格汇总 Top 15 的分析，并给出一句话热点趋势判断（今日舆论主线是什么）。

### 第 3 步：生成产品创意

从"衍生需求"出发，对高价值热点（S/A 级 + 有清晰人群和痛点）逐一生成产品创意。每个创意使用统一模板（见下），最后挑最有潜力的 3 个深度展开、按机会大小排序。

## 产品创意模板

### 创意 N：<一句话产品名>
- **对应热点**：热搜词 + 热度 + 相关性说明
- **核心洞察**：热点背后未被满足的痛点（一句话，说"用户其实想要什么"）
- **目标用户**：人群 + 规模判断
- **产品形态**：小程序 / App / 网页 / AI Agent / 内容产品 / 服务 / 硬件
- **核心功能（MVP）**：3~5 个，按优先级
- **差异化**：与现有产品比独特在哪
- **商业模式**：订阅 / 广告 / 交易佣金 / 增值服务 / 数据服务
- **冷启动路径**：如何借势这个热点获取第一批用户
- **风险与时效**：热点生命周期（小时 / 天 / 周）；热度消退后如何延续
- **可行性评分（1~5）**：需求强度 / 实现难度 / 竞争度 / 变现潜力

### 第 4 步：输出报告

最终输出包含四部分：

1. **热搜快照**：抓取时间、数据源、Top 10 榜单摘要
2. **热点分析表**：Top 15 的结构化分析
3. **产品创意清单**：Top 3（深度展开）+ 其余（一句话简述）
4. **今日机会建议**：一句话总结最适合入局的 1~2 个方向

报告用中文输出，保持紧凑。

## 注意事项

- 数据是**实时快照**，热度和排名随时变化；报告必须标注抓取时间。
- 涉及明星、时政等话题做产品创意时，保持客观中立，不渲染对立情绪。
- 商业化建议应合法合规（不触碰个人信息泄露、版权侵权、灰产等）。
- 若用户只想要某一种结果（只分析不生成创意 / 只要创意清单），按用户要求裁剪，不输出多余内容。
